# 生成能力点 PRP

输入：`$ARGUMENTS`

## 规则

- 只研究和写计划；不修改生产代码，不开始下一能力点，不执行 Git 写操作。
- 输入能力点与当周需求文档的当前能力点不一致时报告差异，不自行替换当前任务。
- 用户未说“下一步”时只能输出计划。
- 只提取与本步直接相关的需求和 D 决策；每项上下文说明必要性。
- 用 `rg`、CMake target 和测试入口调查真实代码；禁止凭模板猜文件、类或命令。
- 陌生或易变 API 查本地安装或官方文档，记录精确版本和章节。
- 检查当前工作区／Git 状态、活动构建目录和无关改动；只读，不清理。

## 生成前必须能回答

1. 这一步改变谁能观察到的什么行为？
2. 哪些现有行为必须保持？
3. 触及哪些协议、表、线程、对象或 UI？
4. 哪些文件是生产者、消费者和测试？
5. 成功、失败、边界、重复、恢复行为是什么？
6. 用户授权到设计、代码、测试、Git 哪一层？
7. 用哪些新鲜命令和人工观察证明完成？

## 输出

保存为 `PRPs/<能力点编号>-<简短中文名称>.md`，按 `PRPs/templates/capability_prp.md` 结构；禁止把 Python／pytest／Docker／npm 等模板命令带入本项目，禁止以行号作为唯一定位方式。

结束时报告：引用的合同、调查文件、未决问题和下一触发。
