# 生成能力点 PRP

输入文件：`$ARGUMENTS`

## 目标

为当前唯一能力点生成一份中文、可执行、可验证、可追踪的上下文包。该命令只研究和写计划，不修改生产代码，不开始下一能力点，不执行 Git 写操作。

## 必须步骤

1. 读取 `AGENTS.md`、`TASK.md` 和输入文件。
2. 确认输入能力点与 `TASK.md` 一致；不一致时报告差异，不自行替换当前任务。
3. 从产品方案、详细设计和学习路线中只提取与本步直接相关的需求和 D 决策。
4. 使用 `rg --files`、`rg`、CMake target 和测试入口调查真实代码；不要凭模板猜文件、类或命令。
5. 检查当前工作区／Git 状态、活动构建目录和无关改动；只读，不清理。
6. 对陌生或易变化 API，优先查本地安装／头文件／官方文档，并记录精确版本和具体章节。
7. 新概念先形成教学包：用途、输入输出、数据结构、顺序、失败、边界、API 表和不超过 30 行示例。
8. 按 `PRPs/templates/capability_prp.md` 生成 PRP。

## PRP 内容要求

- 目标、用户价值、范围、非目标、保持行为和授权；
- 需求／D 决策／路线追踪；
- 每个上下文引用的真实路径和用途；
- 当前与目标文件树；
- 数据、状态、线程、所有权、幂等和恢复；
- 按顺序的具体文件／类／函数／变量任务；
- AI 将补充的测试层级、反例、断言和隔离；
- 真实可运行的验证命令、工作目录、预期结果和清理；
- 文档、学习笔记、交接和 Git 边界；
- 风险、停止条件和一次成功信心。

## 质量门禁

- 不把 Python、pytest、Docker、FastAPI、npm 或模板命令带入当前 C++／Qt 项目，除非真实工程已采用且本步相关。
- 不把整个 D01—D231 或整个仓库塞入 PRP；每项上下文都说明必要性。
- 不以行号作为唯一定位方式，优先真实符号、target 和调用关系。
- 不承诺“一次命令证明生产可用”；自动化与人工验收分开。
- 用户未说“下一步”或 PRP 未确认时，输出只能是计划。

## 输出

保存为：`PRPs/<能力点编号>-<简短中文名称>.md`。

结束时报告：引用的合同、调查文件、未决问题、信心分数和下一门禁。
