# 检查当前能力点

能力点或 PRP：`$ARGUMENTS`

## 规则

- 只在用户说“检查”时进入，不由 AI 自行触发。
- 按 `docs/上下文工程/验证矩阵.md` 选择适用层级，从快到慢执行；任何层失败先定位根因。
- 只运行当前能力点适用的层级，不先跑无关重型测试。
- 构建实际活动目录或 PRP 指定的干净目录后，才信任 CTest 结果。
- 环境不可用时标记“未验证”，禁止记为通过。

## 步骤

1. 读取 `AGENTS.md`、`TASK.md`、对应 PRP 和验证矩阵。
2. 确认源码、构建目录、Preset、Qt／MinGW／vcpkg 版本和 Git 状态。
3. 按序执行适用层级：configure → build → unit／contract → 真实依赖集成 → 故障场景 → 必要时全量回归／性能／安装。
4. 列出必须由用户完成的人工场景和观察点。

## 报告格式

```text
能力点：
构建配置／目录：
工具与依赖版本：
运行命令：
退出码：
通过／失败／跳过：
人工验收：
未验证项：
范围与 Git：
结论：
```

## 判定

- 失败：报告首个根因和影响，不继续声称完成；
- SKIP：记录原因和仍缺的真实证据；
- 自动验证通过／人工验收通过／已交付：只在对应证据齐全时使用。
