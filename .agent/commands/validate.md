# 验证当前能力点

能力点或 PRP：`$ARGUMENTS`

## 原则

本命令不会假设“一个总命令通过就等于应用生产可用”。它必须按 `docs/上下文工程/验证矩阵.md` 选择适用层级，并保留人工 UI／安装／体验验收。

## 步骤

1. 读取 `AGENTS.md`、`TASK.md`、对应 PRP 和验证矩阵。
2. 确认当前源码、构建目录、CMake Preset、Qt／MinGW／vcpkg 版本和 Git 状态。
3. 根据本步影响范围列出验证计划；不要先运行与本步无关的全量重型测试。
4. 构建实际活动目录或 PRP 指定的干净目录，读取退出码和首个失败。
5. 运行相关 unit／contract 测试；再运行必须的真实 MySQL、TLS、Qt SQLite、进程或双 profile 测试。
6. 对故障场景验证失败语义、无关会话存活和恢复。
7. 列出必须由用户完成的人工场景和观察点。
8. 最后才根据需要运行完整回归、性能、安装或发布检查。

## 报告格式

```text
能力点：
构建配置／目录：
工具与依赖版本：
运行命令：
退出码：
通过／失败／跳过：
人工验收：
未验证项：
范围与 Git：
结论：
```

## 判定规则

- 失败：报告首个根因和影响，不继续声称完成；
- SKIP：记录原因和仍缺的真实证据；
- 自动验证通过：只说明指定命令和范围通过；
- 人工验收通过：单独记录用户观察；
- 已交付：只有适用门禁、文档和版本范围全部一致时使用。
