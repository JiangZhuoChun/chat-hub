# 执行能力点 PRP

PRP：`$ARGUMENTS`

## 启动条件

- 当周需求文档的当前能力点与 PRP 一致；
- 用户已说“下一步”或明确要求执行；
- 工作区无关改动已识别并保留。

任一不满足：只报告缺口，不执行修改。

## 执行规则

1. 一次只推进一个 Task；给出目标文件、类／函数、代码、命令和预期结果，由用户落地、构建并观察。
2. 交付前显式列出假设；多种解释全部列出；更简方案必须提出。
3. 只有用户明确要求“帮我实现／修改／修复”时，AI 才直接修改授权范围内的生产文件。
4. 当前 Task 未由用户落地确认前，不展开下一 Task。
5. 生产接口稳定后，AI 直接编写本步测试、fake、夹具和脚本。
6. 验证只报告真实命令、退出码和通过／失败／跳过数；失败按根因定位，不削弱断言。
7. 用户说“检查”时才进入 `validate` 完整分层验证。
8. 每个 Task 交付后同步当周需求与验收文档（实时状态）、PRP 状态和功能代码对照文档。
9. Git 只在明确授权后按文件暂存／提交／推送。

## 红线

- 不推进 PRP 外功能或下一能力点；
- 不覆盖旧工程、用户改动或其他任务文件；
- 不用测试改写产品合同或制造只为通过的生产分支；
- 不以 mock、SKIP、旧二进制或“应该通过”代替真实证据；
- 不自动重放提交结果不明的写操作；
- 不记录或提交秘密、数据库、正文、日志、私钥和构建产物。

## 每个 Task 结束报告

- 能力点、Task、模式；AI 给出的内容与用户／AI 分工；
- 命令、退出码、通过／失败／跳过数（若运行）；
- 风险与未验证项；修改文件与保留的无关改动；
- 下一唯一待办（等待“下一步”“检查”或用户落地反馈）。
