# 执行能力点 PRP

PRP 文件：`$ARGUMENTS`

## 启动门禁

开始前必须全部满足：

- `TASK.md` 指向同一能力点；
- PRP 状态已确认；
- 用户已经说“下一步”或明确要求执行；
- 生产代码、文件操作和 Git 权限没有歧义；
- 当前工作区的无关改动已识别并保留。

若任一条件不满足，只报告缺口和可审查计划，不执行修改。

## 执行流程

1. 重新读取 `AGENTS.md`、`TASK.md`、PRP 和本步直接相关代码／测试／diff。
2. 用中文讲清本步新概念和 API，给最小示例与用户变式。
3. 让用户复述数据流、状态、线程、失败和边界。
4. 一次只执行 PRP 中一个 Task；完成并验证后才进入下一 Task。
5. 生产代码默认由用户编写；AI 提供文件／函数级步骤、审查、提示和调试。
6. 只有用户明确要求“帮我实现／修改／修复”时，AI 才直接修改授权范围内的生产代码。
7. 生产接口稳定后，AI 直接编写本步的测试、fake、夹具和测试脚本。
8. 用户审阅关键断言；AI 运行适用验证并根据真实失败定位根因。
9. 完成人工验收、解释检查、范围审查和文档同步。
10. 只有收到明确 Git 授权后，才按文件暂存、提交或推送。

## 执行红线

- 不推进 PRP 外功能或下一能力点；
- 不覆盖旧工程、用户改动或其他任务文件；
- 不用测试改写产品合同或制造只为通过的生产分支；
- 不以 mock、SKIP、旧二进制或“应该通过”代替真实证据；
- 不自动重放提交结果不明的写操作；
- 不记录或提交秘密、数据库、正文、日志、私钥和构建产物。

## 每个 Task 的结束报告

- 当前能力点和 Task；
- 用户／AI 分别完成了什么；
- 运行命令、退出码和通过／失败／跳过数；
- 发现的风险或未验证项；
- 修改文件和保留的无关改动；
- 掌握状态；
- 是否可以等待用户说“下一步”。
