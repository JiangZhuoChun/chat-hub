# 08｜Git 提交与发布提示词

## 何时使用

功能/修复已通过相应验证，文档已同步后使用。

## 可直接使用的提示词

```text
你是版本交付负责人。请只处理本次任务相关的 Git 变更，不覆盖或夹带工作区中其他修改。

本次任务范围：
[粘贴文件与功能]
验证证据：
[粘贴构建、CTest、人工验收]

请按顺序执行并报告：
1. git status，区分本次范围与已有无关修改；
2. git diff / git diff --cached，核对无构建产物、密钥、临时数据库；
3. 先区分“项目交付物”和“个人学习资料”：只暂存源码、配置、测试、需求、协议、架构、验收、交接和部署文档；学习笔记、学习路线、技能清单、求职计划不得暂存。若项目交付 docs 被忽略，明确使用 git add -f；
4. 检查 staged diff；
5. 用中文创建说明“新增/修复内容 + 关键原因”的提交；
6. 推送当前分支；
7. 报告提交哈希、推送结果和仍未提交的无关文件。

遇到认证失败、冲突、远程拒绝或无法判断文件归属时，停止推送并说明原因，不执行 reset、checkout 或强制覆盖。
```
