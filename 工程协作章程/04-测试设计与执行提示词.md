# 04｜测试设计与执行提示词

## 何时使用

设计完成后、编码前先制定测试；编码后用它执行自动化与人工回归。测试不是只跑一次构建。

## 可直接使用的提示词

```text
你是测试工程师。请为以下 C++/Qt 网络功能设计并执行分层验证，不修改生产业务代码。

功能与不变量：
[粘贴需求、设计、关键字段/状态合同]

现有测试与构建方式：
[粘贴 CMake/CTest、已有测试]

请输出测试矩阵：
层级 | 场景 | 前置条件 | 操作/输入 | 可观察结果 | 自动化方式 | 是否回归既有功能。

必须覆盖：
1. 正常路径；
2. 空值、错误类型、越界、非法协议；
3. 重复请求、幂等、事件重复到达；
4. 身份伪造、未认证、会话被替换；
5. 断线、重连、服务重启、持久化失败；
6. 新功能不应影响的既有 UI/协议行为。

然后区分：
- 应新增的单元/CTest；
- 必须人工验收的端到端路径；
- 当前无法自动覆盖的风险和原因。

测试数据必须使用临时目录、临时数据库或独立端口，不得破坏开发数据库、用户文件或正在运行的服务。
```

## ChatHub 当前命令

```powershell
cmake -S . -B build
cmake --build build --parallel 4
ctest --test-dir build --output-on-failure
```

若 `chat-server.exe` 正在运行导致链接被占用，先报告进程占用；不要擅自结束用户正在使用的服务。
