# ChatHub 工程协作章程与职责提示词库

> 主工作区：`D:\CppLearn\chathub`
>
> 适用项目：ChatHub；其他练习项目仅在用户明确指定时临时切换
> 更新原则：需求、架构、协议、数据模型或工程流程发生变化时，先更新本目录对应文档，再实施代码变更。

## 如何使用

不要把所有提示词一次性交给模型。先根据所处阶段读取一份角色提示词，再连同必要上下文一起发送。

| 阶段        | 先读文档                                | 产出                | 是否可写代码   |
|-----------|-------------------------------------|-------------------|----------|
| 澄清问题、拆需求  | [01-需求分析提示词](01-需求分析提示词.md)         | 需求边界、验收标准、待确认项    | 否        |
| 设计新功能或改协议 | [02-架构与变更设计提示词](02-架构与变更设计提示词.md)   | 模块边界、方案比较、最小改动计划  | 否，等待确认   |
| 已确认方案后编码  | [03-开发实现提示词](03-开发实现提示词.md)         | 可构建的最小实现          | 是        |
| 设计或执行测试   | [04-测试设计与执行提示词](04-测试设计与执行提示词.md)   | 测试矩阵、自动化/人工证据     | 是，仅测试范围  |
| 审查现有改动    | [05-代码审查提示词](05-代码审查提示词.md)         | 有证据的问题清单          | 否        |
| 定位并修复缺陷   | [06-缺陷定位与修复提示词](06-缺陷定位与修复提示词.md)   | 根因、最小修复、回归范围      | 经授权后     |
| 验收、写文档、交接 | [07-验收文档与交接提示词](07-验收文档与交接提示词.md)   | 验收记录、需求/笔记/交接更新   | 是，文档范围   |
| 提交和推送     | [08-Git提交与发布提示词](08-Git提交与发布提示词.md) | 干净、可追溯的提交         | 是，Git 范围 |
| 以学习为目标推进  | [09-学习教练与教学总纲](09-学习教练提示词.md)       | 五步循环、小步练习、审查与掌握证据 | 按教学模式    |

每次都先读 [00-工程协作总章程](00-工程协作总章程.md)。它定义职责边界、质量门禁、文档优先级和“高内聚、低耦合”的共同标准。

## 当前项目的必带上下文

- 相关需求文档；涉及协议时还要带 [ChatHub 协议字段与状态流向总图](../docs/ChatHub协议字段与状态流向总图.md)；
- 只提供本次相关的源码、测试、构建文件和 `git diff`，避免无关上下文污染结论；
- 当前已知约束：Qt Widgets + `QTcpSocket`、Asio ChatServer、Node/JWT 鉴权、SQLite、C++17、CMake/CTest；
- 当前任务目标、不能改变的既有行为、是否允许写代码。
