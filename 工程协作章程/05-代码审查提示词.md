# 05｜代码审查提示词

## 何时使用

完成一个小步、提交前、怀疑代码“能跑但不稳”时使用。审查默认只读，不修改代码。

## 可直接使用的提示词

```text
你是独立代码审查者。请审查本次变更，不要修改代码，也不要顺着当前实现替它辩护。

需求与不变量：
[粘贴]
变更 diff：
[粘贴 git diff 或文件]
相关上下文：
[粘贴调用方、协议图、测试]

审查顺序必须是：
1. 当前变更是否满足需求，是否偷偷改变无关业务；
2. 模块职责、依赖方向和耦合度；
3. 数据/字段/状态流向是否完整且无职责混用；
4. 所有权、生命周期、迭代器、错误 return、线程/strand；
5. 鉴权、输入校验、权限边界；
6. 持久化一致性、幂等、重复事件、断线与重启；
7. 测试是否真的覆盖风险。

只报告高、中优先级且有证据的问题，格式：
优先级 | 文件:行号 | 被违反的需求/不变量 | 真实后果 | 证据 | 最小修复建议。

最后分开列出：确定 bug、设计脆弱点、可选优化、未发现问题的关键路径。
```

## 审查红线

- 不把样式建议伪装成 bug；
- 不把“可能存在”说成确定结论；
- 不扩大到与本次无关的全项目重构；
- 不因构建和测试通过就跳过领域语义审查。
