## 6. 新概念与 API 教学包

### 本步解决什么

安全迁移的最小单位不是“递归复制一个目录”，而是“固定来源快照 + 白名单文件集 + 无覆盖目标 + 复制后证明”。输入是旧仓库的已跟踪文件；输出是新工程中的相同内容和一份可审查映射；失败时停止而不清理或覆盖任何目录。

| API/概念 | 常用形式 | 输入/输出 | 失败与边界 | 常见误用 |
| --- | --- | --- | --- | --- |
| Git 来源快照 | `git rev-parse HEAD`、`git status --short`、`git ls-files` | 提交 ID、脏状态、已跟踪相对路径 | 非 Git 仓库或状态变化时停止 | 只看 HEAD，忽略工作区修改 |
| 绝对路径校验 | `Resolve-Path -LiteralPath` | 输入单一路径，输出规范绝对路径 | 路径不存在或越出新工程时停止 | 用通配符或字符串拼接猜目标 |
| 文件哈希 | `Get-FileHash -Algorithm SHA256 -LiteralPath` | 输入文件，输出内容摘要 | 不能证明目录语义，只证明字节相同 | 哈希一个 build 目录或只比较源不比较目标 |
| 非覆盖复制 | 对每个白名单文件先检查目标不存在，再 `Copy-Item -LiteralPath` | 明确源/目标，输出新文件 | 目标存在、来源状态变化或异常立即停止 | `Copy-Item -Recurse -Force` 覆盖未知内容 |

最小示例（只演示一份文件；实际执行由白名单逐项调用）：

```powershell
$source = 'D:\CppLearn\chathub\CMakeLists.txt'
$target = 'D:\全栈聊天软件\CMakeLists.txt'
if (Test-Path -LiteralPath $target) { throw '目标已存在，拒绝覆盖' }
$before = (Get-FileHash -LiteralPath $source -Algorithm SHA256).Hash
Copy-Item -LiteralPath $source -Destination $target -ErrorAction Stop
$after = (Get-FileHash -LiteralPath $target -Algorithm SHA256).Hash
if ($before -ne $after) { throw '复制后哈希不一致' }
```

变式：把 `$target` 改为已有的 `untitled\CMakeLists.txt`，正确结果应是第一条检查中止；绝不能加 `-Force` 继续。

## 7. 数据流、失败和停止条件

```text
旧 Git HEAD/status + 白名单
  → 校验目标均不存在
  → 逐文件创建目标父目录并复制
  → 目标 SHA-256 与来源比较
  → 复查旧 Git status + 关键哈希
  → 扫描新复制集的禁止路径/文件类型
  → 记录迁移清单
```

- 文件内容所有者始终是用户；本步从不删除、移动、覆盖或修改来源。
- 若旧 Git status 与上述快照不一致、关键源哈希变化、目标路径在执行中出现、复制失败或扫描出禁止项，立即停止，保留已安全创建的文件并报告确切清单；不自动回滚或清理。
- `.env.example` 是可公开的字段模板，不得把它误认为真实环境配置；真实 `.env`、凭据、数据库、证书和私钥永不复制。
- 哈希相等证明复制的文件内容一致；它不证明旧程序已可构建。构建验证明确属于 M0-2。
