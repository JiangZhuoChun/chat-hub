# PRP 示例：M0-1 安全复制旧工程并建立迁移清单

> 本文件展示项目 PRP 应包含的上下文密度，不授权复制、删除、移动、构建或 Git 写操作。真正开始时必须基于当时文件系统和用户确认重新生成正式 PRP。

## 目标

在不改变 `D:\CppLearn\chathub` 的前提下，建立一份可审查的复制计划和迁移清单，把允许的旧工程文件复制到用户确认的新目录，并证明没有携带秘密、数据或构建产物。

## 范围

### 做什么

- 只读列出旧工程版本控制文件、未跟踪文件、构建入口和依赖；
- 把源目录分为复制、排除、待确认三类；
- 检查与新目录 `untitled`、`docs` 和未来目录结构的冲突；
- 用户确认后复制允许文件；
- 比较复制前后旧仓库状态和关键源文件哈希。

### 不做什么

- 不修改任何业务、CMake、协议、数据库或 UI；
- 不删除／覆盖 `untitled`；
- 不复制 `.git`、数据库、秘密、日志、证书私钥、build、node_modules 或学习笔记；
- 不进入 M0-2。

## 新概念与 API

| 概念／命令 | 用途 | 输出／失败 | 边界 |
| --- | --- | --- | --- |
| `git status --short` | 保存旧仓库工作区事实 | 修改／未跟踪列表；非仓库报错 | 只读，不清理 |
| `git ls-files` | 列出版本控制文件 | 相对文件路径 | 不包含未跟踪必要文件 |
| `Get-FileHash` | 比较关键文件内容 | SHA-256 | 不能证明目录语义完整 |
| `Copy-Item -LiteralPath` | 用户确认后复制明确路径 | 目标文件或错误 | 不使用模糊通配符覆盖目录 |
| `Resolve-Path` | 验证源／目标绝对路径 | 规范路径 | 复制前确认目标位于新工程内 |

## 实施蓝图

```yaml
Task 1:
  type: READ_ONLY
  steps:
    - 保存旧仓库 absolute path、HEAD、status 和 tracked file list
    - 列出未跟踪文件并按业务文档、学习资料、数据、构建产物分类
  done_when:
    - 形成来源快照，不执行文件写入

Task 2:
  type: DESIGN
  steps:
    - 对照目标 client-qt/chat-server/shared/db/tools/tests/packaging/assets/docs
    - 形成复制、排除、待确认表
    - 标出与 untitled 和现有 docs 的路径冲突
  done_when:
    - 用户可以逐项审查

Task 3:
  type: MUTATION_REQUIRES_USER_GATE
  steps:
    - 只有用户确认计划后复制明确文件
    - 不覆盖现有路径，遇到冲突立即停止
  done_when:
    - 允许文件位于确认目标，排除项不存在

Task 4:
  type: VALIDATE
  steps:
    - 复查旧仓库 status 和关键哈希
    - 扫描新目录中的数据库、秘密、证书私钥和构建产物
    - 记录复制结果和 M0-2 待办
```

## 停止条件

- 旧仓库状态在操作过程中发生外部变化；
- 新目录已有同名文件且无法确定所有者；
- 发现秘密、数据库或私钥；
- 用户没有确认目标目录或实际复制范围。
