## 10. 实施蓝图

每项必须能单独描述和验证，同一时间只执行一项。

```yaml
Task 1:
  type: READ_OR_DESIGN | MODIFY | CREATE | DELETE
  files:
    - path/to/file
  steps:
    - 找到真实符号或模式，不依赖易漂移行号
    - 说明函数、变量和调用顺序
  preserve:
    - 必须保持的行为
  failure:
    - 失败时的状态和错误
  done_when:
    - 可观察结果

Task 2:
  depends_on: Task 1 已验收
```

| --- | --- | --- | --- | --- |
| 成功 | unit／contract／integration |  |  |  |
| 边界 |  |  |  |  |
| 失败 |  |  |  |  |
| 重复／恢复 |  |  |  |  |

1. 该测试保护哪个合同？

## 13. 文档与记录

- 产品／设计文档：需要更新／无需更新及原因；
- `TASK.md`：状态变化；
- 学习路线：进度和证据；
- 唯一学习笔记：概念、API、理解检查；
- 交接：完成范围、验证、Git 和下一步。

## 14. 风险和停止条件

- 发现会改变产品、公共协议、持久数据或验收的问题时停止并确认；
- 发现旧仓库或用户改动可能被覆盖时停止；
- 连续三次修复失败时回到前提、状态所有权和复现；
- 环境无法验证时标为未验证并保留命令。
