- 不创建任何源码目录、`CMakeLists.txt`、`CMakePresets.json`、`vcpkg.json`、target、测试或构建目录；

## 5. 调用顺序与失败边界

```text
产品／设计合同 → M0-1 目录与 target 边界确认
→ 用户确认 PRP → M0-2 创建最小根 CMake 与实际目录
→ configure（Preset + 工具链）→ build → CTest
```

- `add_subdirectory(...)` 只能指向已存在且带自身 `CMakeLists.txt` 的目录；在本步调用必然是越界。
- CMake 版本存在不等于完整构建输入可用。MinGW 13.1.0 与 Qt 6.11.1 目录已观察到，但 M0-2 配置前仍须验证 Qt 的 CMake 包、架构一致性和 vcpkg 的受控来源。
- Preset 和 vcpkg baseline 必须进入版本控制；用户机器专属的 `CMakeUserPresets.json`、缓存、构建输出和秘密不得进入版本控制。
- 若后续目录职责要求跨越既定依赖方向，先回到 PRP／设计确认，不以临时 include path 绕过边界。
