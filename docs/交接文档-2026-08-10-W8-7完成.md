## 3. 当前客户端架构约束

### 3.1 数据与显示边界

- `m_conversations`：完整 `ChatMessage` 的唯一数据源。
- `QListWidgetItem::data(Qt::UserRole)`：稳定会话身份 `peer`；不能从 `item->text()` 反查会话。
- `QListWidgetItem::text()`：只负责显示名称、未读数、时间和预览，可随 UI 变化。
- `m_unreadCounts`：仅保存未读数 UI 状态，不存消息正文或时间。
- `ChatClient* m_chat`：外部注入的借用指针，`MainWindow` 不负责释放。

### 3.2 已确认的消息模型规则

- `ChatMessage` 负责完整消息：`local_id`、`from`、`to`、`content`、`send_at`、`status`、`failure_reason`。
- 发送消息前 UI 先创建并保存完整模型；通信层只编码和发送。
- 确认/失败事件只携带状态更新模型，UI 必须按 `local_id` 查找已有完整消息，不能把状态更新对象当新消息添加。
- 失败重试必须保留原 `local_id`；重试 Lambda 采用初始化捕获，只保存 `local_id`，不捕获消息引用。

`QStringLiteral(" \\u00B7 %1")`，避免源文件编码造成显示异常。
