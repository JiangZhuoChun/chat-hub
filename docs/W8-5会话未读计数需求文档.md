# W8-5 会话未读计数需求文档

## 1. 目标与非目标

### 目标

当收到非当前会话联系人的消息时，在左侧会话列表显示未读数量；点击该会话后清零。会话的真实身份与列表展示文本分离，未读数量变化不得影响消息存储、切换或发送目标回退。

### 非目标

- 不实现服务端在线列表、已读回执、跨设备同步或消息持久化；
- 不修改 TCP 协议、`ChatMessage`、气泡渲染和消息确认状态机；
- 不实现列表置顶、最后消息预览、搜索或自定义 `QListWidgetItem` 小部件；
- 不改变 `recipientEdit` 优先、当前会话回退的发送规则。

## 2. 数据模型与模块边界

| 数据                                    | 所属模块              | 作用                                |
|---------------------------------------|-------------------|-----------------------------------|
| `m_conversations`                     | `MainWindow` 会话数据 | 保存完整 `ChatMessage`，不保存未读 UI 文本    |
| `m_unreadCounts`                      | `MainWindow` 会话状态 | `peer -> 未读条数`，只由收到对方消息和打开会话更新    |
| `QListWidgetItem::data(Qt::UserRole)` | UI 项数据            | 保存稳定 `peer` 身份                    |
| `QListWidgetItem::text()`             | UI 展示             | 显示 `peer` 或 `peer (N)`，不得作为业务身份来源 |

依赖方向：收到完整 `ChatMessage` → UI 保存会话消息 → 更新未读模型 → 刷新会话项展示。点击会话项 → 从 `UserRole` 读取 peer →
更新当前会话 → 清零未读模型 → 刷新展示与气泡。

## 3. 正常与错误流程

### 收到消息

1. `onChatMessageReceived(const ChatMessage& message)` 将消息加入 `m_conversations[message.from]`。
2. 确保左侧存在该 peer 的会话项，并在 `UserRole` 中保存 peer。
3. 若 `message.from != m_currentPeer`，将该 peer 的未读数加一；若当前正打开该 peer，则未读数保持零。
4. 刷新该会话项文本。
5. 仅当该 peer 是当前会话时重绘气泡。

### 点击会话

1. `onConversationItemClicked()` 从 `item->data(Qt::UserRole)` 取得 peer，不能从显示文本取得。
2. 设置 `m_currentPeer`，将该 peer 未读数清零。
3. 刷新该会话项文本并渲染当前会话。

### 异常与边界

- `item == nullptr`、`UserRole` 中 peer 为空：安全返回，不改变当前会话。
- 收到消息的 `from` 为空属于通信层非法消息，本 UI 功能不额外处理。
- 发送自己的消息不会增加任何未读数。

## 4. 函数与成员清单

| 模块           | 成员/函数签名                                                       | 可见性          | 职责                       | 输入/输出        | 错误行为           | 调用方                             |
|--------------|---------------------------------------------------------------|--------------|--------------------------|--------------|----------------|---------------------------------|
| `MainWindow` | `QHash<QString, int> m_unreadCounts`                          | private      | 保存每个 peer 的未读数           | peer / 数量    | 不保存负数          | UI 状态函数                         |
| `MainWindow` | `void ensureConversationItem(const QString& peer)`            | private      | 确保存在会话项并写入 `UserRole` 身份 | peer / 列表项   | 空 peer 不创建     | 收发消息处理                          |
| `MainWindow` | `void refreshConversationItem(const QString& peer)`           | private      | 根据未读数刷新会话项展示文本           | peer / UI 文本 | 找不到项安全返回       | 未读状态函数                          |
| `MainWindow` | `void markConversationRead(const QString& peer)`              | private      | 将指定 peer 的未读数清零并刷新项      | peer / UI 状态 | 空 peer 安全返回    | 点击会话槽                           |
| `MainWindow` | `void onChatMessageReceived(const ChatMessage& message)`      | private slot | 保存收到消息，按当前会话更新未读数        | 完整消息 / UI 状态 | 保持既有消息校验边界     | `ChatClient` 信号                 |
| `MainWindow` | `void onConversationItemClicked(const QListWidgetItem* item)` | private slot | 按 `UserRole` 切换会话并清零未读   | 列表项 / 当前会话   | 空项或空 peer 安全返回 | `conversationList::itemClicked` |

## 5. 信号与槽

| 发送者           | 信号                                        | 接收者          | 槽                           | 本功能职责              |
|---------------|-------------------------------------------|--------------|-----------------------------|--------------------|
| `ChatClient`  | `chatMessageReceived(const ChatMessage&)` | `MainWindow` | `onChatMessageReceived`     | 仅收到对方消息时累加非当前会话未读数 |
| `QListWidget` | `itemClicked(QListWidgetItem*)`           | `MainWindow` | `onConversationItemClicked` | 清零被打开会话的未读数        |

## 6. 验收标准

- 收到 Bob 消息但当前打开 Carol：Bob 显示未读数，Carol 气泡不变化。
- 点击 Bob：右侧只显示 Bob 会话，Bob 未读数清零。
- 当前打开 Bob 时继续收到 Bob 消息：不增加未读数，消息直接显示。
- 显示为 `Bob (2)` 后仍能正确切换到 Bob、向 Bob 发送和保存 Bob 消息。
- 自己发送消息不会增加未读数。
- 构建通过，既有失败红点、重试、确认状态不受影响。

## 7. 分步实现记录

### 第一步：会话项稳定身份（08-10，已验收）

- `ensureConversationItem()` 改为非 `const`，遍历列表项的 `Qt::UserRole` 查找 peer；找到后立即返回。
- 未找到时才新建 `QListWidgetItem`，显示文本为 peer，并在 `Qt::UserRole` 中保存同一 peer。
- 已验证 Bob、Carol 可同时存在，重复收发 Bob 不会创建第二个列表项；构建和代码审查通过。
- 未读计数的状态模型、累加和清零逻辑尚未实现。

### 第二步：未读状态与列表刷新（08-10，已验收）

- 新增 `m_unreadCounts`，仅保存 `peer -> 未读条数`，不把未读数写入 `m_conversations`。
- `onChatMessageReceived()` 在非当前会话分支中，先递增 `message.from` 的计数，再用同一 `message.from`
  刷新列表项；当前会话只重绘气泡，不增加未读数。
- `onConversationItemClicked()` 从 `Qt::UserRole` 读取稳定 peer，随后调用 `markConversationRead()` 清除该 peer
  的计数并恢复原始展示文本。
- 人工验收：Bob 对 Carol 当前会话连续来两条消息时显示 `Bob (2)`；点击 Bob 后后缀消失并正确显示 Bob 的消息；当前打开 Bob
  时新消息直接显示且不产生未读数。
- 代码审查发现并修复一次参数关联错误：计数键是 `message.from` 时，刷新函数也必须传入 `message.from`，不能传入
  `m_currentPeer`。构建通过，CTest 2/2 通过。
