## 本周功能需求（按能力点顺序）

### M0-1 空白工程根目录与构建边界规划

- **需求**：为新工程固定根目录职责、CMake target 边界和 Git 忽略边界；旧 ChatHub 代码、构建配置和运行依赖一律不迁移。
- **验收**：目录职责与 target 边界有文档级定义；Git 忽略边界写入 `.gitignore`。
- **状态**：已交付（文档级验收完成，PRP 已确认）。

### M0-2 最小根 CMake、Preset、manifest 与首批目录

- **需求**：空白工程可复现构建——根 `CMakeLists.txt`、受控 `CMakePresets.json`（Ninja／MinGW／vcpkg toolchain，Debug／RelWithDebInfo／Release）、manifest `vcpkg.json`（baseline 锁定）和首个接口 target `shared/chathub_contracts`。
- **验收**：从干净 `windows-mingw-debug` 构建目录 configure／build 通过；不创建客户端、服务端、协议或业务占位代码。
- **状态**：已交付（configure／build 自动验证通过）。

### M0-3 最小 CTest smoke 闭环与 test presets

- **需求**：让 `chathub::contracts` 第一次被真实消费者编译和执行：`tests/` 下创建一个 C++20 smoke 可执行 target、`add_test` 注册 CTest，并为三种构建类型增加同名 test presets；无测试时 test preset 必须错误退出，防止“0 tests”假绿。
- **验收**：`ctest --preset windows-mingw-debug` 发现并恰好运行 1 个 smoke 测试，退出码 0；`tests/` 是唯一新增目录。
- **状态**：仅规划（PRP 已生成，等待用户说“下一步”）。

### M0-4 Git 范围

- **需求**：仓库提交只纳入允许文件（合同、协作骨架、构建配置、源码与测试），不含构建产物、本地依赖、秘密和学习资料。
- **验收**：`git status` 分类干净；提交范围经用户明确授权并列出明确文件。
- **状态**：未开始。

> 与路线表的对应：路线 W0 行中“M0-3 Presets／vcpkg”已并入 M0-2 交付；当前仓库的 M0-3 为 CTest smoke 闭环，M0-4 为 Git 范围。

## 阶段验收（不通过不进入 M1）

- [ ] 新仓库不含旧 ChatHub 源码、数据库、秘密、证书私钥、日志、缓存和构建产物。
- [ ] 固定 Qt 6.11.1 MinGW 64-bit、C++20、Ninja、CMake 最低版本、vcpkg commit、`x64-mingw-dynamic` 和依赖版本。
- [ ] 从空构建目录可配置、构建、运行测试和启动新工程基线；本机专属路径只进入 User Preset。
- [ ] 新仓库初始化后只纳入允许文件；本路线和唯一学习笔记不进入 Git。
- [ ] 用户能解释 Preset、target、toolchain、triplet、构建目录和依赖锁定的职责。
