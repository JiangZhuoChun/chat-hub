## 本周功能需求（按能力点顺序）

### M1-1 客户端与服务端分层 CMake 骨架

- **需求**（D199／D208）：建立分层 target——服务端 domain／application／infrastructure／transport，客户端 domain／application／infrastructure／presentation；先用 INTERFACE 表达依赖方向（零占位源码，D207），M1-2 落首批 domain 代码时转 STATIC；app/bootstrap 延后到首个需要 main 的能力点。
- **验收**：configure 期架构断言通过（每层直接链接仅白名单，D221 最小版）；既有 smoke 仍 1/1；负向验证（故意违规链接 → configure FATAL_ERROR → 还原）有效。
- **状态**：已交付（2026-09-01：干净目录 configure／build／CTest 1/1 退出码 0；负向验证正确触发“架构违规”FATAL_ERROR 后还原）。

### M1-2 强类型 ID 与 Outcome

- **需求**（D209／D211）：AccountName、MessageId、LocalMessageId、DeliverySeq、ConversationSeq、RequestId 等轻量强类型，构造／解析时验证格式；不同身份与序号禁止隐式互转；类型化 `Outcome<T>`（`std::variant<T, Error>`）携带稳定 ErrorCode；参数错误与业务冲突不用异常。
- **验收**：domain 纯 C++20（不依赖 Qt／Asio）；非法构造返回错误；单元测试覆盖成功／边界／失败。
- **状态**：自动验证通过（PRP：`PRPs/M1-2-强类型ID与Outcome.md`；Debug CTest 2/2 通过、0 失败、0 跳过）。

### M1-3 协议描述 ProtocolDescriptor

- **需求**（D218）：shared 提供只读 ProtocolDescriptor 注册表：type、名称、方向、允许连接状态、capability、最大正文、默认超时、响应 type；静态编译数据，覆盖设计合同已分配的全部 54 个类型（0x01—0x87）。
- **验收**：测试检查 type 唯一、请求响应配对、连接状态合法；超时与 capability 取值对齐 D74／D197。
- **状态**：已交付（2026-09-01：首验失败两处修正——`has_state` 位掩码、断言期望反写——后干净目录 CTest 3/3 退出码 0；保留 type nullptr 测试已补）。
- **落地补注**（用户）：新增的 `ConnectionState(s)` 关联处已补说明性注释。

### M1-4 安全 FrameDecoder

- **需求**（D07—D09）：8 字节帧头（magic uint16／version uint8／type uint8／body_length uint32，大端）；接收顺序固定：收齐帧头 → 校验 → 分配前拒绝超限 → 收齐正文；单帧 JSON ≤ 65,536 字节双向执行；UTF-8 校验。
- **验收**：半包、粘包、空正文、超长正文、非法 UTF-8、未知 type、版本不兼容均有自动测试；测试链接公开 target（D221）。
- **状态**：已给出待落地（PRP：`PRPs/M1-4-安全FrameDecoder.md`）。
