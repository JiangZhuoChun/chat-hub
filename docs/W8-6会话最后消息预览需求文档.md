# W8-6 会话最后消息预览需求文档

## 1. 目标与非目标

### 目标

在左侧会话列表的每个联系人项中，显示该会话最后一条完整 `ChatMessage` 的正文摘要；未读计数仍显示在联系人名称上。摘要必须从
`m_conversations` 推导，不建立第二份“最后消息”缓存。

### 非目标

- 不修改 TCP 协议、`ChatMessage`、`ChatClient` 或服务端；
- 不实现会话置顶、按时间排序、消息持久化、搜索或自定义列表项控件；
- 不改变现有未读数、点击清零、发送目标回退、失败重试和气泡渲染；
- 不在会话列表中展示消息 ID、发送者 ID 或失败原因。

## 2. 数据来源与展示规则

| 数据        | 唯一来源                                        | 规则                        |
|-----------|---------------------------------------------|---------------------------|
| 联系人身份     | `QListWidgetItem::data(Qt::UserRole)`       | 永远保存原始 `peer`             |
| 联系人名称与未读数 | `peer`、`m_unreadCounts`                     | 第一行显示 `peer` 或 `peer (N)` |
| 最后一条消息正文  | `m_conversations[peer]` 的最后一个 `ChatMessage` | 第二行显示正文摘要                 |
| 列表文本      | `QListWidgetItem::text()`                   | 纯展示，不参与查找和存储              |

正文摘要规则：将换行替换为空格；当正文长度超过本轮定义的展示上限时截断并追加省略号；没有任何消息时显示“暂无消息”。

## 3. 正常与错误流程

1. 新收到消息或本地消息进入会话后，消息写入方调用 `refreshConversationItem(peer)`。
2. `refreshConversationItem()` 使用 `UserRole` 找到该 peer 对应的列表项。
3. 它读取未读数和最后一条消息正文，组合出两行展示文本并设置到该项。
4. 点击会话清零未读后仍调用同一刷新函数，因此只改变第一行的 `(N)`，第二行摘要保持不变。

边界：peer 为空或找不到列表项时安全返回；会话不存在或消息列表为空时显示“暂无消息”；展示截断不得修改 `ChatMessage::content`。

## 4. 函数与成员清单

| 模块                      | 函数签名                                                         | 可见性          | 职责                        | 输入/输出        | 错误行为                    |
|-------------------------|--------------------------------------------------------------|--------------|---------------------------|--------------|-------------------------|
| `mainwindow.cpp` 匿名命名空间 | `constexpr int kConversationPreviewMaxLength = 24`           | 文件内部         | 统一限定摘要展示字符数               | 无 / 最大字符数    | 不是协议或业务常量，不向其他模块暴露      |
| `MainWindow`            | `QString makeConversationPreview(const QString& peer) const` | private      | 从会话完整模型生成最后消息的纯展示摘要       | peer / 摘要文本  | 空 peer、无会话或无消息时返回“暂无消息” |
| `MainWindow`            | `void refreshConversationItem(const QString& peer)`          | private      | 组合联系人、未读数和摘要，刷新指定列表项      | peer / 列表展示  | peer 为空或找不到项时安全返回       |
| `MainWindow`            | `void onSendClicked()`                                       | private slot | 本地消息写入会话后刷新接收者项摘要         | 用户输入 / UI 状态 | 保持已有输入校验与发送规则           |
| `MainWindow`            | `void onChatMessageQueued(const ChatMessage& message)`       | private slot | 仅在防御性补建本地消息时刷新该会话摘要       | 完整消息 / UI 状态 | 保持已有状态更新逻辑              |
| `MainWindow`            | `void onChatMessageReceived(const ChatMessage& message)`     | private slot | 收到消息后刷新发送者项摘要，无论该会话是否当前打开 | 完整消息 / UI 状态 | 保持既有未读计数规则              |

本轮不新增成员变量。`m_conversations` 是消息数据的唯一真相；`m_unreadCounts` 是未读状态的唯一真相。

## 5. 调用点约束

| 消息写入位置                        | 写入后必须刷新谁       | 原因                                 |
|-------------------------------|----------------|------------------------------------|
| `onSendClicked()`             | `message.to`   | 本人新发消息也应成为该会话的最后预览                 |
| `onChatMessageQueued()` 的补建分支 | `message.to`   | 防御性补建路径同样会产生最后消息                   |
| `onChatMessageReceived()`     | `message.from` | 当前会话和非当前会话都必须更新摘要；只有未读数递增仍只属于非当前分支 |

## 6. 验收标准

- Bob 收到或发送一条消息后，列表显示 Bob 和该消息正文摘要。
- Bob 有两条未读时，第一行显示 `Bob (2)`，第二行仍显示最后一条消息摘要。
- 点击 Bob 后，`(2)` 消失，摘要不丢失；仍能按 `UserRole` 正确切换会话。
- 正文含换行或超长文本时，列表中为单行、可控长度的摘要，原消息气泡正文不被修改。
- 构建通过；既有未读、气泡、失败重试与确认状态不受影响。

## 7. 实现与验收记录（08-10，已验收）

- `makeConversationPreview()` 只读 `m_conversations`：无消息返回“暂无消息”，正文换行规范为单行，超过 24 个 UTF-16
  单元时追加单字符省略号；截断点若落在高代理项后会回退一个单元，避免生成无效 UTF-16。
- `refreshConversationItem()` 以 `UserRole` 定位会话项，统一生成 `peer\npreview` 或 `peer (N)\npreview`；展示文本不参与业务查找。
- `onSendClicked()`、`onChatMessageQueued()` 的补建分支和 `onChatMessageReceived()` 均在新增消息后刷新正确
  peer。接收路径在当前会话渲染或非当前会话未读数递增完成后，只进行一次最终刷新。
- 人工验收：本地发送、当前会话收到、非当前会话收到均立即更新摘要；非当前会话显示未读数，点击后未读数清零但摘要保留；气泡、重试与确认状态保持正常。
- 质量验证：Qt Lint 无输出，`cmake --build build --parallel 2` 通过，`ctest --test-dir build --output-on-failure` 为 2/2
  通过。
