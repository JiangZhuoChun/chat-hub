# 当前能力点验证矩阵

验证必须从快到慢分层执行，但只运行当前能力点实际适用的层级。任何层失败都先定位根因；不得用旧结果、SKIP 或弱化断言继续宣布完成。

## Level 0：范围与合同

- 当前 PRP 已确认，任务仍是唯一能力点；
- 产品需求和 D 决策有明确追踪；
- 生产代码、测试、文档和 Git 授权边界明确；
- 当前 diff 不包含无关文件、秘密或生成物。

## Level 1：配置与静态结构

- CMake configure 成功；
- target 依赖符合分层；
- 禁止 include／namespace 扫描通过；
- clang-format／clang-tidy 只运行项目已配置规则；
- 不因工具未配置而临时发明不可复现命令。

## Level 2：编译与链接

- 构建实际活动 IDE 目录或 PRP 指定的干净目录；
- 记录完整命令、配置、退出码和首个错误；
- 客户端、服务端、shared、admin 和相关测试 target 按影响范围构建；
- 不使用上一次成功二进制代替当前构建。

## Level 3：单元与状态测试

- AI 为 domain、值对象、mapper、FrameDecoder、状态转换或 Controller 编写测试；
- 覆盖成功、边界和失败；
- 测试从公共行为验证，不复制同一实现算法；
- 用户解释关键断言和构造的反例。

## Level 4：合同测试

- fake、MySQL、SQLite 或其他 adapter 运行相同 port 合同；
- 双端 codec 运行相同协议样例；
- stable type／error／schema 不重复、不漏配；
- fake 通过不能替代真实实现。

## Level 5：真实依赖集成

- 真实 MySQL 8.4.11、MariaDB Connector/C、TLS、私有 CA、Qt SQLite 或 Windows API；
- 使用临时 schema、端口、证书、目录和 profile；
- 记录环境版本和清理结果；
- 环境不可用时标记“未验证”，不记为通过。

## Level 6：故障与恢复

- 断线、重连、慢客户端、队列满、数据库写失败、提交未知、低磁盘、证书错误和进程重启中与本步相关的场景；
- 验证失败不伪装成功、无关会话仍存活、持久事实可恢复；
- 自动重试只发生在合同允许的只读或明确回滚路径。

## Level 7：端到端与人工体验

- 同机两个 `--profile` 客户端连接真实服务端；
- 完整用户路径从 UI／客户端输入到数据库事实和另一客户端观察；
- DPI、IME、托盘、视觉、键盘和提示文字由用户人工验收；
- 自动化不能取消人工 UI 验收。

## Level 8：性能、安装与发布

- 100 在线账号、50 条／秒、10 分钟、成功率／重复／丢失和 P95；
- 干净 Windows 11 x64 断网安装与卸载；
- Client／Server 安装包、许可证、ACL、服务和防火墙；
- 42 条需求和 D01—D231 追踪矩阵。
