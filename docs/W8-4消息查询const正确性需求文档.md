# W8-4 消息查询 const 正确性需求文档

## 1. 目标与非目标

### 目标

消除 `MainWindow::findMessageByLocalId()` 在 `const` 成员函数中通过 `const_cast` 返回可写 `ChatMessage*`
的设计问题。当前调用者都需要修改消息状态，因此将查询函数改为非 `const` 成员函数，保持现有重试、确认、失败状态更新行为不变。

### 非目标

- 不修改 `ChatMessage` 的成员、消息协议、会话存储结构或状态机；
- 不改变 `findMessageByLocalId()` 的查找范围、空 ID/未知 ID 的返回规则；
- 不修改 UI 布局、信号槽参数或网络层。

## 2. 模块与依赖

- 影响模块：`client-qt/MainWindow` 的会话消息查询辅助模块。
- 数据所有权：`m_conversations` 继续拥有所有 `ChatMessage`；查询函数只返回非拥有指针。
- 依赖规则：当前调用者都通过非 `const MainWindow` 查询并修改消息状态；出现真实只读调用场景后，再按需要增加 `const` 重载。

## 3. 正常与错误流程

1. 调用者带有效 `local_id` 查询本地会话。
2. 找到消息时，返回可修改消息指针，供现有状态更新和重试逻辑使用。
3. 空 ID 或遍历结束仍未找到时，返回 `nullptr`。
4. 调用者必须在解引用前判断空指针；既有槽函数继续显示提示并安全返回。

## 4. 函数清单

| 模块           | 函数签名                                                         | 可见性     | 职责              | 输入/输出     | 错误行为                 | 调用方                      |
|--------------|--------------------------------------------------------------|---------|-----------------|-----------|----------------------|--------------------------|
| `MainWindow` | `ChatMessage* findMessageByLocalId(const QString& local_id)` | private | 为状态更新和重试查找可修改消息 | ID / 可写指针 | 空或未知 ID 返回 `nullptr` | `onRetryClicked()`、状态更新槽 |

## 5. 验收标准

- 不再出现 `const_cast<ChatMessage*>`。
- 非 `const` 查询函数可供现有状态更新与重试逻辑修改消息。
- 函数不再声明为 `const`，与当前“查找后需要修改状态”的调用意图一致。
- 空 ID、未知 ID、失败红点和重试行为保持正确。
- `cmake --build build --parallel 2` 通过。

## 6. 实现与验收记录（08-10）

- 查询函数已改为非 `const`，不再使用 `const_cast`。
- 内层循环使用 `ChatMessage&`，返回地址指向 `m_conversations` 的真实元素，不再返回局部副本地址。
- 空 ID 与未知 ID 仍返回 `nullptr`；构建和代码审查通过。
